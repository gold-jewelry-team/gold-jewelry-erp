# 黃金珠寶進銷存暨營運管理系統

本專案為獨立的黃金珠寶門市／倉庫管理系統，與家庭記帳系統使用不同 Repository、資料庫及部署服務。

## 技術架構
- Python 3.12
- FastAPI
- PostgreSQL
- SQLAlchemy 2.x
- Alembic
- Docker
- Render（雲端部署）；同一程式碼保留店內 LAN 部署彈性

## 目前階段
這是第一階段的可執行專案骨架，提供健康檢查、資料庫連線檢查、環境設定及 Alembic migration 基礎。尚未完成正式進銷存交易功能，也尚未連接正式資料庫或部署。

## 本地啟動
1. 複製 `.env.example` 為 `.env` 並設定 `DATABASE_URL`。
2. 安裝依賴：`pip install -r requirements.txt`
3. 啟動：`uvicorn app.main:app --reload --host 0.0.0.0 --port 8000`
4. 開啟 `/docs` 查看 API。

## API
- `GET /health`：應用程式存活狀態
- `GET /health/db`：資料庫連線狀態

## 設計原則
- 門市、倉庫及其他儲存位置分開管理。
- 商品單件條碼唯一；庫存數量與庫存異動流水分離。
- 調貨採來源／目的位置雙邊交易並保留紀錄。
- 金價、舊金回收、舊金換新及補差額計價，待業主提供正式公式後才實作；不可使用示意公式作為正式成交依據。
- 先建立雲端版，不預設離線雙向同步；未來如需離線交易，另行設計佇列及衝突處理。
- PostgreSQL 不直接暴露公網；店內 LAN 部署時由內網應用程式連線資料庫。

## 開發路線
1. 基礎架構與公司／據點／儲存位置
2. 商品主檔、分類、單件條碼
3. 庫存餘額、庫存流水、調貨
4. 廠商、採購、到貨驗收、入庫
5. 每日盤點與差異處理
6. 金價、舊金回收／換新、銷售與收付款
7. 權限、稽核、報表、備份與復原測試

## 注意
目前骨架不應直接用於正式營運。正式上線前仍需完成 migration、權限、稽核、交易一致性、測試、備份及資安檢查。
